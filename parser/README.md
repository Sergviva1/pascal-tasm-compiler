# Парсер — ЛР № 1, вариант № 10

`pascal_parser` разбирает `program`, необязательные объявления `integer` и блок `begin…end.` с простыми присваиваниями (`x := 10`, `y := x`). Имена регистронезависимы. Проверяются синтаксис, повторные объявления, диапазон литерала `0…32767`, пределы массивов (100 переменных и 100 присваиваний независимо). Разрешение имён в операторах и проверка типов выражений не входят в ЛР № 1. [РБНФ всего варианта](../docs/grammar.ebnf) отдельно помечает реализованное подмножество; [описание диалекта](../docs/language.md) объясняет границы этапов.

## Сборка и запуск из корня проекта

Требуются компилятор C++17 и CMake ≥ 3.16. DOSBox и TASM не нужны.

```sh
cmake -S . -B build
cmake --build build
(cd build && ctest --output-on-failure)
./build/parser/parser_cli parser/tests/lab1/T1.pas
./build/parser/parser_lab1_tests T1
```

`parser_cli` получает токены от существующего лексера и выводит AST и таблицу символов в stdout. При ошибке выводит диагностику в stderr без частичного AST. Коды: `0` — успех; `1` — неверные аргументы или ошибка открытия/чтения файла; `2` — лексическая ошибка (в том числе недопустимый байт NUL); `3` — ошибка парсера. Библиотечная точка входа — `pascal::parser::parse` из [`parser.hpp`](parser.hpp). Вход — `const TokenStorage&`; результат содержит `Program` из `shared/ast_v1.hpp` и таблицу. При ошибке возвращается пустой результат и первая диагностика.

## Автономные тесты

`parser_lab1_tests` собирает `TokenStorage` непосредственно в [`tests/lab1/tests.cpp`](tests/lab1/tests.cpp) и не линкуется с лексером или генератором. Аргумент `T1`, `T2`, `T3` или `T4` выбирает вход; `--boundaries` проверяет пределы 100/101 и дополнительные случаи. `.pas` рядом — эквивалентные входы для чтения и проверки `parser_cli`. CTest сверяет вывод и код завершения с эталоном как для автономных тестов, так и для CLI.

[Ожидания T1–T4](tests/lab1/EXPECTED.md) и точные эталоны `tests/lab1/expected/` отделены от [фактических результатов](results/lab1/), полученных автономным запуском.
