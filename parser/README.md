# Парсер Pascal

Реализован синтаксический анализ методом рекурсивного спуска и семантические проверки из §2 ТЗ.

## Сборка и запуск

Из корня репозитория:

```bash
mkdir -p build
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -I. -o build/parser.exe parser/main.cpp
./build/parser.exe tests/tokens.lst
```

Вход — JSON-массив токенов. После полного успешного разбора в текущем каталоге создаются `tree.json` и `symbols.tab` с отступами 2 пробела. При синтаксической/семантической ошибке файлы не создаются и существующие результаты не перезаписываются. Ошибки открытия/записи выходных файлов сообщаются отдельно; файловая запись двух результатов не является атомарной транзакцией.

Не запускайте парсер из `tests/`: там лежат эталоны.

## Возможности

- `const`, `var`, процедуры с параметрами по значению и по ссылке;
- глобальные и локальные объявления, затенение глобальных имён;
- регистронезависимое разрешение имён; ссылки AST используют написание из объявления;
- рекурсивные вызовы и вызовы ранее объявленных процедур;
- присваивания, составные операторы, `if/then/else`, все шесть сравнений;
- арифметика с приоритетами, левой ассоциативностью, скобками и унарным минусом;
- проверка дублей, необъявленных имён, типов, количества/типов аргументов;
- аргумент `var`-параметра — только изменяемая переменная или параметр;
- проверка формата токенов, номеров строк и единственного конечного `EOF`.

Константы по грамматике — один целочисленный либо boolean-литерал, не выражение. Целые литералы проверяются на диапазон C++ `int` (как при `std::stoi`, указанном в ТЗ). Вложенные процедуры и обращения к ещё не объявленным процедурам не поддерживаются. Допускаются пустые блоки и один завершающий `;` перед `end`. `else` относится к ближайшему незавершённому `if`.

## Тесты

```bash
bash parser/run_tests.sh
```

Скрипт собирает парсер и тесты с `-O2 -Wall -Wextra -Wpedantic`, затем проверяет:

- объявления: `parser/declaration_tests.cpp`;
- полное AST и символы эталонного примера, приоритеты, области видимости, параметры, рекурсию, сравнения и ошибки: `parser/parser_tests.cpp`;
- каждый обрезанный префикс эталонного потока токенов;
- реальный CLI во временном каталоге, сравнение выходов с эталонами;
- неправильный JSON/формат токенов, синтаксические/семантические ошибки;
- отсутствие выходных файлов при ошибках и сохранность предыдущих результатов.

`parser_tests.cpp` использует только тестовый построитель токенов для строк с разделёнными пробелами словами и знаками. Это не реализация лексера. Эталонный тест читает настоящий `tests/tokens.lst`.

Скрипт предназначен для Bash / Git Bash. Можно выбрать компилятор через `CXX=clang++`. В Git Bash скрипт ставит каталог выбранного компилятора первым в `PATH`, чтобы не смешивать DLL разных MinGW.

Полная цепочка и сборка ASM требуют готовых лексера и кодогенератора, затем TASM/TLINK. Тесты парсера не проверяют исполнение ASM.
