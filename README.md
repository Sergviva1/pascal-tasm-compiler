# Анализатор подмножества Pascal — вариант № 10

Наша часть — синтаксический и семантический анализ. Начать с [плана](PLAN.md) и [контрактов с лексером и генератором](docs/interfaces.md). Реализация начинается с ЛР № 1; процедуры и указатели пока описываются только в полной грамматике.

## Задача для исполнителя ЛР № 1

1. Прочесть методичку и формулировку в `docs/`. Подготовить описание диалекта и полную РБНФ, явно отделив реализуемый сейчас минимум.
2. Подготовить автономные входы и ожидаемые результаты по разделу 1 плана. У каждого токена есть категория, лексема, строка и столбец. Включить тесты повторного имени в другом регистре и синтаксической ошибки.
3. На C++17 без STL-контейнеров реализовать парсер минимальной программы, AST v1, таблицу символов, диагностику и печать результатов. Проверить границы фиксированных массивов. Интерфейсы соседей не менять молча.
4. Дать команды чистой сборки и запуска тестов через CMake/CTest. Для отчёта сохранить входы, ожидаемые и фактические результаты. Для сборки из Git не требовать локальный каталог `check/` и DOSBox.

## Работа с Git

- `main` — принятые этапы; `lr1/parser` — разработка первой лабораторной с последующим pull request в `main`.
- `check/` — локальные справочные копии; не публикуем чужие отчёты, готовые программы и дистрибутивы инструментов. Для собственной работы достаточно зафиксированного контракта и автономных тестов.
- Если напарники захотят вести здесь свои исходники, от нового `main` заводим `lr1/lexer` и `lr1/codegen`. Каждый присылает только свой исходный код и тесты отдельным pull request; общий заголовок согласуем и добавляем один раз. Веток-свалок для содержимого `check/` не нужно.
