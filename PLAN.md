# План: синтаксический и семантический анализатор Pascal

Наша зона ответственности: токены → разбор → AST и таблица символов либо диагностика с позицией. Лексер и генератор ASM делают напарники. Основание — личное задание в `parser/variant.txt`, общий вариант и методичка в `docs/`. Разрабатываем по одной ЛР: сначала согласуем ожидаемый результат, затем реализуем, запускаем автономные тесты и показываем результат на приёмку.

Этот план относится к `parser/` (ветка `team/parser`). Библиотеки `lexer/` и `codegen/` уже собираются независимо; для парсера используем контракты из `shared/`. Первый результат на проверку — полная РБНФ и четыре тестовых входа, не реализация всего языка. `PLAN.md` и `parser/variant.txt` остаются в `team/parser`. Для PR создай ветку от `main` и перенеси в неё только коммиты реализации (`git cherry-pick`), без коммитов личных материалов. Держи их изменения в отдельных коммитах.

## 4. ЛР № 4 — процедуры, указатели и интеграция

- [ ] Реализовать объявления и вызовы процедур, параметры, локальные переменные и области видимости. Проверять число и типы аргументов.
- [ ] Реализовать `^integer`, `@` и разыменование в выражении и слева от `:=`. Запретить взятие изменяемого адреса константы. Обновить контракт генератора до внесения изменений.
- [ ] Приёмка: разобрать пример ниже и пример с локальной переменной. Отдельно проверить передачу значения вместо адреса, неверное число аргументов и обращение к локальному имени снаружи. Вывести полное AST в консоль и файл.

```pascal
program Demo;
const Limit = 10;
var x: integer;
procedure RaiseToLimit(p: ^integer);
begin
  if p^ < Limit then p^ := Limit
end;
begin
  x := 3;
  RaiseToLimit(@x)
end.
```

Наш результат: дерево с вызовом, взятием адреса и разыменованием, корректные типы и области видимости. Проверка `x = 10` после исполнения — сквозной тест команды, а не замена автономному тесту парсера.
